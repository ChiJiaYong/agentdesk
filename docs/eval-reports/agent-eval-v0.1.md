# Agent 路径评测报告 v0.1 — 图级轨迹断言

日期：2026-11-20 · 任务：10（6 风险类）· 模型：确定性规则演示层 · 全部零 API 成本

## 设计

任务脚本化（Scripted 模型 / 规则演示模型），但**穿过真实的图、真实业务工具、真实护栏**，
断言落在轨迹上而非最终文本：

- 工具调用序列与参数来源（订单号必须来自用户文本）
- 护栏拒绝是否出现在轨迹中（伪造 id → 类型化拒绝 → 模型恢复）
- 工具三态结果是否被如实转述（error/unknown 不得产生肯定性回复）
- 幂等重放是否可见（`"replayed": true`）
- 写操作是否触发 HITL（needs_human / risk_flags）

## 覆盖（6 风险类 × 10 任务，全部通过）

| 风险类 | 任务 |
|---|---|
| 正常流 | 状态查询（工具结果锚定回答）/ 金额查询 / 双工具序列 / 评论上下文 |
| 缺参 | 未提供订单号 → 必须追问，不得调用工具 |
| 伪造参数 | 编造订单号 → 护栏拒绝 → 模型改为追问 |
| 工具故障 | 格式合法但库里不存在的订单 → NOT_FOUND → 如实转述"无法找到" |
| 后果型动作 | create_ticket → needs_human=True（HITL 队列可见） |
| 幂等重放 | 同幂等键重放 → 返回原工单（`replayed: true`），不产生重复行 |

## 评测体系价值实证

**本评测在合并前抓到一个真实 bug**：`validate` 节点重建 AIMessage 时未复用原消息 id，
`add_messages` 将其作为新消息追加，导致存活的工具调用被执行两次。副作用未造成事故
（幂等键返回原工单），修复方式为复用原消息 id 原位替换，并留下回归任务
`two_tool_sequence`。这一案例是"轨迹断言 > 文本断言"的直接证据。
