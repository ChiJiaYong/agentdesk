# 3 分钟演示脚本（录制指引）

> 录制准备：`docker compose up`（或本地 uvicorn）+ 工作台页面（localhost:8000）+
> llama-server 已启动（本地模型层）。屏幕录制 1080p，语速自然，总共约 3 分钟。

## 0:00–0:20 开场（一页话）

> "这是 AgentDesk——面向跨境电商独立站的客服 Agent 平台。它解决一个真实痛点：
> 中小卖家请不起 7×24 客服，而通用聊天机器人查不了订单库、保证不了金额一致、
> 也不敢自动执行退款。左边的 Agent 跑在真实的 99,441 笔订单数据上。"

## 0:20–1:00 正常流程（工具调用 + 引用溯源）

输入：`Where is my order e481f51cbdc54678b7cc49136f2d6af7?`

> "客户问物流。注意 Agent 没有编造——它调用 get_order_status 查真实订单库，
> 回答里的状态和日期全部来自工具返回。"

再输入：`What is your return policy?`

> "政策类问题走另一条路：混合检索（BM25+向量+重排）查知识库，回答带引用。
> 知识库是三份官方法规原文和 2999 条真实客户问答，每条数据都有来源、许可证、
  抓取日期三元组。"

## 1:00–1:50 高风险动作与人审（本项目的灵魂）

输入：`The item from order e481f51cbdc54678b7cc49136f2d6af7 arrived damaged, I want a refund.`

> "客户要退款。Agent 不会自己执行——它创建工单草稿，右边的人审队列立刻出现。
> 我点批准，工单才落到状态 approved。全过程有幂等键保护：同一个请求重放一百次，
> 也只有一张工单。这就是'写操作必须过人审'的护栏设计。"

## 1:50–2:20 评测体系（最值钱的 30 秒）

> "这个项目最值钱的是评测。三层：检索消融（混合比单路高 7.4 个百分点）、
> 10 个图级轨迹断言任务——它们曾抓到一个工具被重复执行的真 bug，
> 以及真实模型上的 Pass^k 业务可靠性口径——能力上限和可靠性是两回事，
> p=0.6 时 Pass@5 是 99%，Pass^5 只有 7.8%。每个数字都能一条命令复现。"

（可切屏展示 docs/eval-reports/ 下的两份报告）

## 2:20–2:50 模型三档 + 工程规范

> "模型层三档可切换：零配置演示、本地 GGUF（Qwen2.5-7B，数据不出本机，
> 原生工具调用）、或者你在设置窗口粘贴 API key——图、工具、护栏、轨迹
> 在层间完全一致，因为模型交换只是评测变量，不是重写。整个项目 11 个 PR
> 全部走受保护主干的 CI 门禁，每个设计决策都有 ADR 和理论书的章节引用。"

## 2:50–3:00 收尾

> "仓库、评测报告、设计决策全在 GitHub，欢迎拷打。"

---

### 录制要点

- 每次输入前等上一轮完全返回；失败重试不剪（真实感加分）
- 设置窗口展示一次三档选择（不真正切换也行）
- 若展示 trace：`runs/` 下最新 JSON 打开，指出 steps 数组与 token 统计
- 备用：若网络不好，全程本地层演示（零外部依赖）
