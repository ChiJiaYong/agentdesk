# ADR-0001: 编排选型 — 产品 Agent 用 LangGraph，手写循环仅作理解参考

日期：2026-11-19 · 状态：已接受

## 约束

- 开发者为应届生，代码以"看得懂、讲得出"为先；面试需能解释框架底层机制
- 项目是中小厂求职作品：JD 明确要求 LangChain/LangGraph 使用经验
- 理论依据必须可回溯《深入理解AI Agent》v2.0

## 候选方案

1. **纯手写 Harness 循环**（书 §2.2.4 路线）：可控性最强，但工程量大、面试有"是否照抄开源"的质疑风险，且与目标 JD 的框架要求错位
2. **LangGraph**：JD 高频；书 §1.2.4.4 定位"工作流+自主编排，适合复杂多步骤工作流"；节点即函数，每个节点 30–80 行可独立讲清；自带 checkpoint/HITL 中断恢复
3. Dify/低代码：简历说服力弱于代码框架，排除

## 决策

产品 Agent（support/kbuddy）用 **LangGraph** 编排；`core/mini_loop.py` 保留约 120 行手写 ReAct 循环作为**理解参考实现**（配测试与 demo），并在注释/笔记中与 LangGraph 逐点对照。

## 代价

- 引入框架抽象层：需要额外理解 State/图语义（通过对照练习消化）
- 框架升级风险：锁定 langgraph>=0.2 版本下限，升级走 changelog

## 替代方案的复活条件

若后续遇到 LangGraph 无法表达的控制流（如复杂动态拓扑），回到方案 1 的自定义节点函数——LangGraph 节点本就是普通函数，迁移成本低。
