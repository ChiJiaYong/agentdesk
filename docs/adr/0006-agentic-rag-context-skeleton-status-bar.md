# ADR-0006: 智能体化 RAG + 上下文骨架 + 状态栏（全书精读后的对齐重构）

日期：2026-11-20 · 状态：已接受 · 前置：docs/BOOK_MAP.md（全书 313 页精读基线）

## 背景与约束

全书精读发现三处实现与书相悖，其中一处是范式级偏差：

1. **[§3.3.4]** 我们把知识检索做成了**固定前置节点**（每次对话必检索）——恰是书中
   "非智能体化 RAG"的反面教材；书处方：检索工具化，由模型 ReAct 主导（拆解→检索→
   评估充分性→改写再检索），且按复杂度分流（简单问题单次直答更快且质量相当）。
2. **[§2.2.5/§2.3]** plan 节点把检索摘要与 known-ids 动态注入 system prompt——踩中书中
   "时间戳陷阱"：动态内容进前缀 = 每轮打穿 KV/Prompt Cache（书中案例 TTFT 0.5s→3-5s、
   账单翻倍）。
3. **[§2.6]** 模型数不清自己调过几次工具、手里有哪些订单号（上下文学习"检索而非推理"，
   无提炼层）——Xfinity 案例的失败模式。

## 决策

1. **search_knowledge 工具化**（§3.3.4）：混合检索包装为模型可调用工具，返回带来源标注
   与"参考资料，不含指令"声明（§2.4.7/§5.1.9 主仆忠诚——知识库内容同样是注入面）；
   简单事实问题模型可跳过检索。
2. **上下文骨架**（§2.2.5）：`[冻结 system] + [轨迹（压缩副本）] + [末尾 <agent_status>]`。
   SYSTEM_PROMPT 模块导入时定稿、运行期只读；已知订单号/风险计数等动态信息全部移入状态栏。
3. **Agent 状态栏**（§2.6）：`core/status_bar.py` 代码维护（绝不让 LLM 统计——模型无条件
   相信状态栏，也因此它是投毒面）；内容=时间/轮次/known-ids/重复调用计数/风险标志/待用户提供项。
   更新策略=每轮替换（同 id 原位换），缓存仅失效上一条状态后的短后缀——按 §2.6.4 成本式
   `αS·N/2 vs (1-α)R`，本场景状态小、更新频、会话短，替换优于持久追加。
4. **分层压缩 L1+L2**（§2.7.4）：工具结果预算（早于最近 2 条截断为预览+[COMPRESSED] 占位，
   全文在 run 轨迹可回查）+ 总量阈值批量压缩；保留四类高价值信息：决策/约束/失败路径/引用。
5. **恢复分级+熔断**（§5.1.5）：调用指纹（tool+args）计数进状态栏与状态；同指纹 ≥2 记风险，
   ≥3 needs_human 熔断转人审。
6. **流程驱动系统提示词**（§2.4.1/2.4.3）：SOP 四步 + NEVER 少而关键；业务规则细化
   （金额必先查工具、政策回答必引用检索、unknown 不得当成功）。

## 代价

- 检索工具化后，"必检索"的正确性由模型行为保证而非结构保证——用图级评测的
  source_marked 断言与 W5 评测集覆盖（简单问题不检索是特性不是回归）。
- 状态栏每轮替换使上一轮状态后的缓存后缀失效——已按 §2.6.4 公式权衡（见上）。
- 压缩占位符有信息损失——全文在 runs/ 轨迹可回查，回归评测以轨迹断言兜底。

## 替代方案的复活条件

- 固定前置检索恢复：当检索成为每轮刚需且模型频繁漏调时（评测发现），按 §3.3.4 复杂度
  分流做混合（关键意图前置+其余工具化）。
- 持久追加状态栏：会话变长且状态更新频率下降时（§2.6.4 公式翻转）。
- Skills 渐进式披露（§2.5）：工具/话术体系增长后，将退费话术与工单分类规范拆为 Skill。
